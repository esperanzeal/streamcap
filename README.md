# StreamCap

> 解决 NDM / IDM 无法下载的**鉴权 m3u8 视频**下载器（Chrome 扩展）

很多网站的视频流（m3u8 分片）需要携带浏览器里的 Cookie / Origin / Referer 才能下载，常规下载器（NDM、IDM 等）拿不到这些鉴权信息，直接下载会报 403。StreamCap 直接跑在浏览器里，**自动复用当前浏览器会话的鉴权信息**，像打开网页一样下载。

## 特性

- 🔍 **自动嗅探**：监听页面请求 + 扫描 `<video>` 标签，自动发现 m3u8 流（无需手动抓包）
- 🔑 **全自动鉴权**：分片请求自动携带浏览器 Cookie / Origin / Referer，无需手动配置
- 🔐 **AES-128 解密**：自动读取 m3u8 里的密钥信息并解密分片
- ⚡ **并行分片下载**：每个任务 4 线程并行拉取分片，断点续传（分片缓存到浏览器 OPFS，中断后从断点继续）
- 📋 **下载管理页**：任务队列、全局并发控制（1/2/4/8/16/无限，默认 4）、暂停/继续/重试、进度与速度显示
- 🔁 **自动重试**：任务失败自动重试 ≤3 次（指数退避）；取消/暂停不会误触发
- 🧩 **重复检测**：同一视频重复添加时，任务名自动加序号 `(2)(3)` 提醒
- 📝 **日志系统**：按日期记录下载全过程（嗅探/调度/分片/导出/下载器信号），可查看、导出 txt
- 💾 **下载信号同步**：等 Chrome 下载管理器确认落盘完成才标记"已完成"，避免"显示完成但没文件"
- 🔌 **右键菜单**：任意页面右键 → "嗅探视频" 一键扫描并打开管理页

## 安装

1. 打开 Chrome，访问 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点击 **加载已解压的扩展程序**，选择本项目目录
4. 建议固定扩展图标到工具栏

> ⚠️ 需要 **Chrome 116+**（manifest 已声明最低版本）。加载后若提示"无法加载"，请确认浏览器版本。
> ⚠️ 修改代码后需在扩展页点 **刷新** 按钮重新加载。

## 使用

1. 打开视频页面（自动嗅探），点击扩展图标查看嗅探到的 m3u8 列表
2. 点击 **⬇️ 加入下载**（同一视频会标记重复序号，别重复添加）
3. 打开下载管理页（扩展弹窗 📂 按钮，或右键菜单"嗅探视频"自动打开）
4. 等待任务完成——文件会保存到 Chrome 默认下载目录
5. 出问题先打开 📋 日志页看记录

### 并发任务

管理页右上角"并发任务"下拉框控制**同时下载的任务数**：

- 改大（如 4 → 8）：更多排队任务开始下载
- 改小（如 8 → 4）：自动"全部暂停 → 全部继续"，多余任务回队列等补位
- `无限`：不限制任务数（慎用，会占满带宽）

"线程"下拉框控制**单个任务内**并行拉取分片的线程数（默认 4）。

### 断点续传说明

- 分片保存在浏览器的 OPFS（Origin Private File System），**关闭标签页/浏览器后分片还在**（同一站点数据保留期内）
- 中断/失败后点 **继续** 或 **重试**，会跳过已下载的分片
- **下载完成前请保持视频页面打开**：最终文件是从页面内存中的 blob 触发 Chrome 下载的，关页会导致导出中断

## 常见问题

| 问题 | 处理 |
|---|---|
| 下载显示"已完成"但目录里没文件 | 打开 📋 日志，看 `[下载器]` 记录：文件可能因重名被 Chrome 自动改名（`xxx (1).mp4`），在下载管理器里搜文件名 |
| 任务卡在"等待中"不动 | 检查并发任务数是否被占满；刷新扩展后会自动恢复调度 |
| 分片报 403 / Failed to fetch | 站点风控或临时网络问题，任务会自动重试 3 次；仍失败则稍后手动重试 |
| 浏览器重启后任务变失败 | 正在"导出中"的任务在重启时会失败——先检查下载目录，文件可能已保存 |
| 右键"嗅探视频"没反应 | 确认扩展已加载、页面允许注入脚本；刷新页面后重试 |

## 技术说明

- **架构**：MV3 Service Worker（调度/队列/嗅探/状态机）+ content script（分片下载/合并/AES 解密）
- **下载流程**：嗅探 → 入队 → 分片并行下载（OPFS 缓存）→ 合并 → 交给 `chrome.downloads` 落盘 → 等 `onChanged` 信号确认 → 标记完成 + 清理分片
- **容错**：SW 空闲重启不影响下载（下载在 content script 里跑）；重启后自动重建任务队列并重新调度；下载完成信号缓存重放，防止丢失导致误判重复下载
- **调度**：`maybeDispatch` 全局并发调度，每个标签页至多同时跑 1 个任务
- **目录结构**

```
background.js        后台：队列/调度/嗅探/状态机/下载信号同步
content.js           页面侧：分片下载/断点续传/AES-128 解密/合并
manifest.json        扩展清单
popup/               扩展弹窗（嗅探列表 + 加入下载）
manager/             下载管理页（任务列表 + 设置）
logger/              按日期查看/导出日志
```

## 开发

- 改动后：`chrome://extensions/` 里点刷新
- 调试：Service Worker 的控制台、页面控制台（`[VGP]` 前缀日志）、📋 日志页
- 语法检查（有 Node 时）：

```bash
node --check background.js && node --check content.js
```
