# StreamCap

> 浏览器内运行的**多格式视频下载器**（Chrome 扩展）——解决 NDM / IDM 无法下载的鉴权视频流

很多网站的视频流（m3u8 分片 / MP4 直链 / DASH）需要携带浏览器里的 Cookie / Origin / Referer 才能下载，常规下载器（NDM、IDM 等）拿不到这些鉴权信息，直接下载会报 403。StreamCap 直接跑在浏览器里，**自动复用当前浏览器会话的鉴权信息**（含完整 Referer、Cookie、浏览器身份），像打开网页一样下载。

## 特性

- 🔍 **自动嗅探**：监听页面请求 + 扫描 `<video>` 标签，自动发现 **HLS(m3u8) / DASH(mpd) / MP4 直链 / FLV** 流（无需手动抓包）
- 📏 **文件大小探测**：MP4 直链显示实际大小（Range 探测，方便按大小选清晰度——部分站点等无清晰度标注的场景）
- 🔑 **全自动鉴权**：请求自动携带浏览器 Cookie / 完整 Referer / 身份，无需手动配置；支持需要 CDN 会话 Cookie 的站点
- 🔐 **AES-128 解密**：自动读取 m3u8 密钥并解密分片（支持 key rotation，多密钥轮换流也能正确解密）
- ⚡ **多格式下载**：HLS 分片、MP4 直链（Range 分块 + 流式降级）、DASH 分片（init 段 + media 段拼接），全部支持断点续传（OPFS 缓存）
- 📋 **下载管理页**：任务队列、全局并发控制（1/2/4/8/16/无限，默认 4）、暂停/继续/重试、进度与速度显示
- 🔁 **自动重试**：任务失败自动重试 ≤3 次（指数退避）；取消/暂停不会误触发
- 🧩 **重复检测**：同一视频重复添加时，任务名自动加序号 `(2)(3)` 提醒
- 📝 **日志系统**：按日期记录下载全过程（嗅探/调度/分片/导出/下载器信号），可查看、导出 txt
- 💾 **下载信号同步**：等 Chrome 下载管理器确认落盘完成才标记"已完成"，避免"显示完成但没文件"
- 🔌 **右键菜单**：任意页面右键 → "嗅探视频" 一键扫描并打开管理页

## 能力边界

| 能下载 | 不能下载 |
|--------|---------|
| HLS（m3u8 + AES-128 解密） | DRM/EME 加密流（Widevine 等，下载了也是加密垃圾） |
| MP4 直链（Range 分块 / 流式降级） | 私有协议/URL 加密在 JS 里计算的流（嗅探不到，如 YouTube） |
| DASH（mpd，未加密分片） | 需要特殊站点解析器才能拿到的流（youtube-dl 式适配） |
| 任意网站的标准视频流（零配置、通用逻辑） | 需要登录 Cookie 且页面未登录的站 |

> 注：部分站点等 DASH 分轨站的"视频轨"下载后**无音轨**（音视频分离是这类站的设计，浏览器播放时混合）；合并音轨需要额外开发。

## 安装

1. 打开 Chrome，访问 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点击 **加载已解压的扩展程序**，选择本项目目录
4. 建议固定扩展图标到工具栏

> ⚠️ 需要 **Chrome 116+**（manifest 已声明最低版本）。加载后若提示"无法加载"，请确认浏览器版本。
> ⚠️ 修改代码后需在扩展页点 **刷新** 按钮重新加载。

## 使用

1. 打开视频页面（自动嗅探），点击扩展图标查看嗅探到的视频流列表（带格式标签 HLS/DASH/MP4 和文件大小）
2. 点击 **⬇️ 加入下载**（同一视频会标记重复序号，别重复添加）
3. 打开下载管理页（扩展弹窗 📂 按钮，或右键菜单"嗅探视频"自动打开）
4. 等待任务完成——文件会保存到 Chrome 默认下载目录
5. 出问题先打开 📋 日志页看记录

### 并发任务

管理页右上角"并发任务"下拉框控制**同时下载的任务数**：

- 改大（如 4 → 8）：更多排队任务开始下载
- 改小（如 8 → 4）：自动"全部暂停 → 全部继续"，多余任务回队列等补位
- `无限`：不限制任务数（慎用，会占满带宽）

"线程"下拉框控制**单个任务内**并行拉取分片的线程数（1-8，默认 4）。

### 断点续传说明

- 分片保存在浏览器的 OPFS（Origin Private File System），**关闭标签页/浏览器后分片还在**（同一站点数据保留期内）
- 中断/失败后点 **继续** 或 **重试**，会跳过已下载的分片
- **下载完成前请保持视频页面打开**：最终文件是从页面内存中的 blob 触发 Chrome 下载的，关页会导致导出中断

## 常见问题

| 问题 | 处理 |
|---|---|
| 下载显示"已完成"但目录里没文件 | 打开 📋 日志，看 `[下载器]` 记录：文件可能因重名被 Chrome 自动改名（`xxx (1).mp4`），在下载管理器里搜文件名 |
| 任务卡在"等待中"不动 | 检查并发任务数是否被占满；刷新扩展后会自动恢复调度 |
| 分片报 403 / Failed to fetch | 站点风控、URL 签名过期（部分站点等直链有时效）、或临时网络问题——重新嗅探换新 URL，或稍后重试 |
| 下载的是 MP4/DASH 但没声音 | 部分站点等 DASH 分轨站音视频分离，单视频轨无音轨（属站点设计，非 bug） |
| 浏览器重启后任务变失败 | 正在"导出中"的任务在重启时会失败——先检查下载目录，文件可能已保存 |
| 右键"嗅探视频"没反应 | 确认扩展已加载、页面允许注入脚本；刷新页面后重试 |
| 某影视站嗅探不到 | 私有协议/DRM 加密流（如 YouTube、爱奇艺加密流）——见"能力边界"，不做特殊适配 |

## 技术说明

- **架构**：MV3 Service Worker（调度/队列/嗅探/状态机）+ content script（分片下载/合并/AES 解密）
- **下载流程**：嗅探（格式识别 HLS/DASH/MP4）→ 入队（记录格式）→ 按格式分流下载（HLS 分片 / MP4 Range 分块 / DASH 分片，OPFS 缓存）→ 合并 → 交给 `chrome.downloads` 落盘 → 等 `onChanged` 信号确认 → 标记完成 + 清理分片
- **鉴权/CORS**：下载在视频页面 content 里 fetch（自动带完整 Referer + Cookie）；webRequest 给视频响应注入具体 origin 的 CORS 头（支持 credentials 携带跨域 CDN 会话 Cookie）
- **容错**：SW 空闲重启不影响下载（下载在 content script 里跑）；重启后自动重建任务队列并重新调度；下载完成信号缓存重放；停滞判定按"分片数 90s 未增长"踢出占槽任务
- **调度**：`maybeDispatch` 全局并发调度（promise 链串行化），每个任务有 `priority` 序号（创建 FIFO / 点击优先 = 减到最小 / 停滞重排 = 加到最大），每标签页至多 1 个任务
- **目录结构**

```
manifest.json        扩展清单
src/background/      Service Worker（ES module）：main 入口/state 状态/scheduler 调度/sniffing 嗅探+格式识别/formats 格式判断/signals 下载信号/stalled 停滞心跳/log 日志/messages 消息常量
src/content/         页面侧（多文件共享 window.VGP）：main 入口/opfs 缓存/formats 格式判断/hls 解析解密/downloader 下载循环(HLS/MP4/DASH)/merge 合并/sniffer 嗅探/log 日志
popup/               扩展弹窗（嗅探列表 + 格式标签 + 大小 + 加入下载）
manager/             下载管理页（任务列表 + 设置）
logger/              按日期查看/导出日志
```
