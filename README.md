# StreamCap

> 浏览器内运行的**多格式视频下载器**（Chrome 扩展）——解决 NDM / IDM 无法下载的鉴权视频流

很多网站的视频流（m3u8 分片 / MP4 直链 / DASH）需要携带浏览器里的 Cookie / Origin / Referer 才能下载，常规下载器（NDM、IDM 等）拿不到这些鉴权信息，直接下载会报 403。StreamCap 直接跑在浏览器里，**自动复用当前浏览器会话的鉴权信息**（Referer 与同站 Cookie），像打开网页一样下载。

## 特性

- 🔍 **自动嗅探**：监听页面请求 + 扫描 `<video>` 标签，自动发现 **HLS(m3u8) / DASH(mpd) / MP4 直链 / FLV** 流（无需手动抓包）
- 📏 **文件大小探测**：MP4 直链显示实际大小（Range 探测，方便按大小选清晰度（无清晰度标注时尤其有用））
- 🔑 **自动鉴权**：请求在视频页面上下文发起，浏览器自动带上 Referer 与同站 Cookie，无需手动配置
- 🔐 **AES-128 解密**：自动读取 m3u8 密钥并解密分片（支持 key rotation；`METHOD=NONE` 明文段与不支持的加密方式会按明文保留而不是错解）
- ⚡ **多格式下载**：HLS 分片（含 fMP4 init 段）、MP4 直链（Range 分块 + 流式降级）、DASH 分片（init 段 + media 段拼接）；除 MP4 流式降级路径外均支持断点续传（OPFS 缓存）
- 📋 **下载管理页**：任务队列、全局并发控制（1/2/4/8/16/无限，默认 4）、暂停/继续/重试、进度与速度显示、失败定位
- 🔁 **自动重试**：任务失败自动重试 ≤3 次（3s/6s/9s 线性退避）；取消/暂停不会误触发
- 🔗 **智能续传/接管**：重试时自动寻找可用的同源承载页（原页面已关则自动打开原视频页）；承载页按「并发任务」数分散，不会把多个任务堆到同一个页面上
- 📊 **队列排序可切**：队列中任务可按「创建时间」或「进度」排序（管理页切换）；下载中的任务位置固定，出一个进一个
- ⚡ **实时速度**：按最近 4 秒的字节增量显示当前速度（不是全程平均值）；页面停摆/无数据时自动清空，不会僵在旧数字上
- 🧩 **重复检测**：同一视频重复添加时（按 URL 主体判定，忽略签名参数差异），提示"续传该任务？"或标记重复序号 `(2)(3)`
- 🗜️ **流式合并导出**：页面右下角按钮可在超大文件（`chrome.downloads` 读 blob 会 OOM 的级别）时逐批写盘保存，不占内存、不经过下载器
- 📝 **日志系统**：按日期记录下载全过程，保留最近 7 天，可查看、筛选、导出 txt
- 💾 **下载信号同步**：等 Chrome 下载管理器确认落盘完成才标记"已完成"，避免"显示完成但没文件"
- 🔌 **右键菜单**：任意页面右键 → "嗅探视频" 一键扫描并打开管理页

## 能力边界

| 能下载 | 不能下载 |
|--------|---------|
| HLS（m3u8 + AES-128 解密，含 fMP4/EXT-X-MAP） | DRM/EME 加密流（Widevine 等，下载了也是加密垃圾） |
| MP4 直链（Range 分块 / 流式降级） | 私有协议/URL 加密在 JS 里计算的流（嗅探不到，如 YouTube） |
| DASH（mpd，未加密分片） | 需要特殊站点解析器才能拿到的流（youtube-dl 式适配） |
| 任意网站的标准视频流（零配置、通用逻辑） | 需要登录 Cookie 且页面未登录的站 |
| 服务器返回 CORS 头（或扩展能按 URL 模式注入）的视频 | **URL 无媒体扩展名且服务器不返回 CORS 头**的 CDN（浏览器不允许扩展为无法按模式匹配的请求注入响应头） |
| HLS 每分片独立 URL 的流 | **单文件 BYTERANGE 式 fMP4**（所有分片都是同一个文件的字节段，靠 `#EXT-X-BYTERANGE` 切）——会重复下载整个文件，暂不支持 |

> 注：DASH 分轨站的"视频轨"下载后**无音轨**（音视频分离是这类站的设计，浏览器播放时混合）；合并音轨需要额外开发。

## ⚠️ 自动化行为（须知）

以下行为是**有意设计**，没有 UI 开关（自用项目，按使用习惯固化）：

1. **删除终态任务会关闭其来源标签页**——删除"已完成/失败/已取消"任务时，若该标签页没有其他未完成任务，会一并关闭（释放内存；失败页通常也已失效）
2. **重试时会自动寻找或打开承载页**——优先复用任务自己的来源页（你当前看的那个页面），其次复用已打开的同源页；都没有才新建承载页
3. **「🗜️ 合并导出」按钮按需出现**——只在该网站确实存在本扩展的分片缓存时显示，普通页面不注入
4. **承载页按并发数创建，一个标签页只跑一个任务**——扩展按你设置的「并发任务」数维护承载页（优先复用已打开的同源页，没有才在后台新建）；任务结束后承载页留给下一个任务复用，空闲 5 分钟自动关闭
5. **页面停摆时会自动刷新该页面恢复下载**——某任务连续 90s 既无下载进展也无网络活动、但页面仍活着（典型是浏览器对标签页节流）时，会自动刷新该标签页并重新注入任务（分片保留在 OPFS，进度接着续传）；同一任务最多刷新 3 次，之后才标失败

## 安装

1. 打开 Chrome，访问 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点击 **加载已解压的扩展程序**，选择本项目目录
4. 建议固定扩展图标到工具栏

> ⚠️ 需要 **Chrome 116+**（manifest 已声明最低版本）。加载后若提示"无法加载"，请确认浏览器版本。
> ⚠️ 修改代码后需在扩展页点 **刷新** 按钮重新加载。

## 使用

1. 打开视频页面（自动嗅探），点击扩展图标查看嗅探到的视频流列表（带格式标签 HLS/DASH/MP4 和文件大小）
2. 点击 **⬇️ 加入下载**（同一视频会标记重复序号或提示续传已有任务）
3. 打开下载管理页（扩展弹窗 📂 按钮，或右键菜单"嗅探视频"自动打开）
4. 等待任务完成——文件会保存到 Chrome 默认下载目录
5. 出问题先打开 📋 日志页看记录（支持按关键字筛选）

### 并发任务

管理页右上角"并发任务"下拉框控制**同时下载的任务数**：

- 改大（如 4 → 8）：更多排队任务开始下载
- 改小（如 8 → 4）：自动"全部暂停 → 全部继续"，多余任务回队列等补位
- `无限`：不限制任务数（慎用，会占满带宽）

"线程"下拉框控制**单个任务内**并行拉取分片的线程数（1-8，默认 4）。

### 断点续传与失败重试

- 分片保存在浏览器的 OPFS（Origin Private File System），**关闭标签页/浏览器后分片还在**（同一站点数据保留期内）
- 中断/失败后点 **继续** 或 **重试**，会跳过已下载的分片；**失败任务的重试会自动寻找/打开承载页**（见"自动化行为"）
- **下载完成前请保持视频页面打开**：最终文件是从页面内存中的 blob 触发 Chrome 下载的，关页会导致导出中断
- **超大文件（数 GB 以上）**：`chrome.downloads` 读取 blob 时可能内存不足——失败后请改用页面右下角 **🗜️ 合并导出**（逐批流式写盘，不占内存）。分片始终保留在 OPFS，不会丢

## 常见问题

| 问题 | 处理 |
|---|---|
| 下载显示"已完成"但目录里没文件 | 打开 📋 日志，看 `[下载器]` 记录：文件可能因重名被 Chrome 自动改名（`xxx (1).mp4`），在下载管理器里搜文件名 |
| 任务卡在"等待中"不动 | 检查并发任务数是否被占满；刷新扩展后会自动恢复调度 |
| 分片报 403 / Failed to fetch | 站点风控、URL 签名过期（部分直链有时效）、或临时网络问题——重新嗅探会提示"续传该任务"，续传即可；无后缀 CDN 见"能力边界" |
| 下载的是 MP4/DASH 但没声音 | DASH 分轨站音视频分离，单视频轨无音轨（属站点设计，非 bug） |
| 重试后任务卡显示"找不到可用的同源页面" | 该站当前没有可用的同源标签页——打开原视频页面（或页面直接续传）再重试 |
| 浏览器重启后任务变失败 | 正在"导出中"的任务在重启时会失败——先检查下载目录，文件可能已保存 |
| 右键"嗅探视频"没反应 | 确认扩展已加载、页面允许注入脚本；刷新页面后重试 |
| 某影视站嗅探不到 | 私有协议/DRM 加密流（如 YouTube、爱奇艺加密流）——见"能力边界"，不做特殊适配 |

## 技术说明

- **架构**：MV3 Service Worker（入口 / 状态 / **调度池** / 嗅探 / 宿主选择 / 信号 / 停滞 / 日志）+ content script（分片下载 / 合并 / AES 解密 / OPFS），共享 `window.VGP`
- **下载流程**：嗅探（格式识别 HLS/DASH/MP4）→ 入队（记录格式）→ 按格式分流下载（HLS 分片 / MP4 Range 分块 / DASH 分片，OPFS 缓存）→ 合并（用 OPFS 的 File 对象组装 Blob，避免大文件读回内存）→ 交给 `chrome.downloads` 落盘 → 等 `onChanged` 信号确认 → 标记完成 + 清理分片
- **CORS**：由声明式网络规则（`declarativeNetRequest`，`cors_rules.json`，7 条按媒体类型/后缀匹配）为视频响应注入 `Access-Control-Allow-Origin: *`，并**设置（set）**暴露 `Content-Range / Content-Length / ETag / Accept-Ranges`（用 `set` 保证头一定存在——`append` 在头缺失时是否创建未文档化，可能静默不生效）；由 Chrome 引擎执行，不依赖 Service Worker 存活
- **容错**：SW 空闲重启不影响下载（下载在 content script 里跑）；重启后自动重建队列与运行表并重新调度；下载完成信号缓存重放；**停滞判定按"90s 既无进度增长也无任何网络活动"**（content 每次分片请求尝试都会上报活动，慢下载/坏分片重试不会被误判）；宿主标签页被关/冻结/回收时自动迁移到同源页；页面"停摆"（活着但完全没进展）则刷新该页重新注入续传
- **调度（v5）**：任务排在一个**全局就绪队列**里（不再按标签页分队列），由 `pool.js` 的调度循环派发——并发槽位满就等，任务结束立刻补位（"出一个进一个"）；每个任务独占一个承载页（一页一任务）；承载页同源复用、空闲回收；**队列排序**支持"创建时间 / 进度百分比"两套（管理页可切）；「优先下载」= 有空槽直接插队，满槽则顶掉**已下载进度最少**的运行中任务（被顶掉的任务 3 秒后回队首续传，进度不丢）
- **目录结构**

```
manifest.json        扩展清单（含 declarative_net_request 规则集）
cors_rules.json      响应头注入规则（CORS / Content-Range 暴露）
src/background/      Service Worker（ES module）：main 入口/state 状态/pool 调度池（队列+槽位+承载页）/scheduler 入队与暂停取消/sniffing 嗅探+格式识别/formats 格式判断/signals 下载信号/stalled 停滞心跳与停摆刷新/host 宿主标签页选择/log 日志
src/content/         页面侧（多文件共享 window.VGP）：main 入口/opfs 缓存/formats 格式判断/hls 解析解密/downloader 下载循环(HLS/MP4/DASH)/merge 合并导出/sniffer 嗅探/log 日志
popup/               扩展弹窗（嗅探列表 + 格式标签 + 大小 + 加入下载）
manager/             下载管理页（任务列表 + 设置）
logger/              按日期查看/筛选/导出日志
```

## 开发

- 改动后：`chrome://extensions/` 里点刷新
- 调试：Service Worker 的控制台、页面控制台（`[VGP]` 前缀日志）、📋 日志页
- 语法检查（需 **Node ≥ 22**，其 `node --check` 能自动识别 ES module）：

```bash
for f in src/background/*.js src/content/*.js; do node --check "$f"; done
```
